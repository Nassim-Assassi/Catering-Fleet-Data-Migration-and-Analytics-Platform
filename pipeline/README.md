# ETL Pipeline

A Python-based Extract-Transform-Load (ETL) pipeline that incrementally extracts food truck transaction data from MySQL, validates and transforms it, and loads it to S3 as partitioned Parquet data for Athena/Glue querying.

## Overview

The pipeline processes food truck transaction data through three stages:

1. **Extract** — Read the `DIM_Truck` and `DIM_Payment_Method` tables in full, and read only new rows from `FACT_Transaction` (`transaction_id` greater than the last saved offset)
2. **Transform** — Validate expected columns/types, drop rows with invalid field values, and derive `year`/`month`/`day` columns from the transaction timestamp
3. **Load** — Upload the transformed data to S3 as Parquet: dimension tables are overwritten, and transactions are appended and partitioned by `year`/`month`/`day`

After a successful load, the highest `transaction_id` processed is saved as the new offset to `s3://<bucket>/offset.json`, so the next run only picks up transactions created after this run.

## Prerequisites

- Python 3.8+
- MySQL RDS database with data loaded
- AWS credentials configured (for reading/writing the S3 bucket)
- Docker (optional, for containerized execution)

## Installation

### Local Setup

1. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```

2. Create a `.env` file in the workspace root with:
   ```
   DB_USER=<mysql_username>
   DB_PASSWORD=<mysql_password>
   DB_HOST=<mysql_host>
   DB_NAME=<database_name>
   S3_BUCKET_NAME=<s3_bucket_name>
   AWS_ACCESS_KEY_ID=<your_key>
   AWS_SECRET_ACCESS_KEY=<your_secret>
   AWS_REGION=<aws_region>
   ```
   (AWS credentials can be omitted if the AWS CLI is already configured with a default profile.)

## Usage

### Run Locally

```bash
cd pipeline
python pipeline.py
```

The script will:
- Connect to MySQL and read the current offset from `offset.json` in S3
- Extract dimension tables in full and only new transactions
- Transform and validate all tables
- Load the transformed data to S3 as Parquet
- Save the new offset to S3 only after the load succeeds
- Write status logs to the console

### Run Individual Modules

`extract.py`, `transform.py`, and `load.py` can each be run directly for local debugging. They read/write intermediate CSV files (paths defined in `paths.py`) instead of chaining in memory:

```bash
python extract.py    # writes extracted_*.csv
python transform.py  # reads extracted_*.csv, writes transformed_*.csv
python load.py        # reads transformed_*.csv, uploads to S3
```

### Run with Docker

```bash
cd pipeline
docker-compose up
```

Docker will build an image, apply environment variables from `../.env`, and run `pipeline.py` in a container.

### Deploy and Run on AWS (ECS Fargate)

- `deploy_pipeline.sh` — Builds the Docker image, pushes it to ECR, and reports the deployment details. The pipeline is then run automatically by an EventBridge schedule (`cron(15 10,13,16 ? * MON-FRI *)` — 10:15, 13:15, and 16:15 UK time, Monday-Friday).
- `run_pipeline.sh` — Manually triggers a one-off ECS Fargate task run and waits for it to complete, reporting the exit code.

Both scripts read AWS/ECS configuration from a `.env` file in the workspace root (generated by `terraform apply`).

## Output

After successful execution:
- New/changed dimension data is stored at `s3://<bucket>/Food_Trucks/DIM_Truck` and `s3://<bucket>/Food_Trucks/DIM_Payment_Method` (overwritten each run)
- New transactions are appended to `s3://<bucket>/Food_Trucks/FACT_Transaction`, partitioned by `year`, `month`, `day`
- The latest processed `transaction_id` is saved to `s3://<bucket>/offset.json`

## Modules

- **extract.py** — Connects to MySQL, queries the truck/payment method tables in full and transactions since the last offset
- **transform.py** — Validates expected columns/types, filters invalid field values, converts `has_card_reader` to boolean, and derives `year`/`month`/`day` columns
- **load.py** — Uploads transformed data to S3 as Parquet (overwrite for dimensions, append + partition for transactions)
- **offset_helpers.py** — Reads/writes the transaction offset (`offset.json`) to/from S3
- **logging_config.py** — Configures shared console logging for all pipeline scripts
- **paths.py** — Defines local CSV file paths used when running modules individually

## Troubleshooting

- **Database connection fails** — Check DB_HOST, DB_USER, DB_PASSWORD, DB_NAME in .env
- **`S3_BUCKET_NAME is not set`** — Ensure S3_BUCKET_NAME is present in .env
- **`No new transactions to process`** — All transactions up to the saved offset have already been loaded; this is expected if the pipeline runs before new data arrives
- **AWS upload fails** — Verify AWS credentials are configured (via .env or AWS CLI) and have S3 access
- **Data validation errors** — Review logs for which columns failed type/value checks in transform.py
